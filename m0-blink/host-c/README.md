# host-c · біти в «регістрі» (чистий C на хості)

> Розбір до [`reg.c`](reg.c). Сам код тримаємо коротким — уся теорія тут.
> Мета вправи: відчути, що `digitalWrite(pin, HIGH)` — це просто **запис біта в байт**,
> і дорогою прогнати ланцюг компіляції руками (кроки — у [README модуля](../README.md)).

## Модель: байт = 8 ніжок

«Регістр» GPIO-порту — це один байт у пам'яті, де **кожен біт керує однією ніжкою**
(pin). Біт = 1 → на ніжці високий рівень (LED горить), 0 → низький. Біти й піни
нумеруються **з нуля, справа наліво**:

```
 біт:   7   6   5   4   3   2   1   0
 pin:  p7  p6  p5  p4  p3  p2  p1  p0
 знач:  0   0   1   0   0   1   0   0    = 0x24 (hex) = 36 (dec)
                ^           ^
              pin5        pin2
```

`0x24` — це hex-запис (кожна hex-цифра = 4 біти; у C нема друку в двійковому вигляді,
тому hex зручніший за десяткове для «бітового» коду). Увімкнені біти 5 і 2 → горять
pin5 і pin2; решта ніжок існують, просто зараз = 0.

## Шпаргалка бітових операторів (ядро embedded-C)

Спершу будуємо **маску** — байт з єдиним увімкненим бітом на потрібній позиції:

```
(1u << pin)   зсув ліворуч: беремо 1 і «зсуваємо» на pin позицій
              1u << 0 = 00000001
              1u << 2 = 00000100
              1u << 5 = 00100000
```

> **Чому `1u`, а не `1`?** `1` — це signed `int`; зсув одиниці у/через знаковий біт
> (напр. `1 << 31`) — це **Undefined Behavior**. `1u` — unsigned, поведінка визначена.
> Звичка з першого дня. ⤳ UB — головний ворог у M2.

Далі маскою діємо на регістр (`a |= b` — це скорочення `a = a | b`):

| Операція | Що робить | Ідіома |
|---|---|---|
| `\|` (АБО / OR) | ставить біти в 1 там, де в масці 1; решта без змін | `reg \|= mask` → **set** |
| `&` (І / AND) | лишає 1 тільки де в **обох** 1; решта → 0 | перевірка/виділення біта |
| `~` (НЕ / NOT) | інвертує **всі** біти: `~(1u<<2)=11111011` | маска «все, крім біта 2» |
| `&= ~mask` | «І з інверсією маски» гасить саме цей біт | → **clear** |
| `^` (XOR) | перемикає біт (1↔0) там, де в масці 1; решта без змін | `reg ^= mask` → **toggle** |

**Read-modify-write.** Усі три (`set/clear/toggle`) — це патерн «прочитати регістр →
змінити один біт → записати назад». На залізі це реально 3 операції по шині; якщо між
ними втрутиться переривання — буде **гонка**. ⤳ critical section / ISR-safe — M3/M7.

## Вказівники: чому `uint8_t *reg`, а не `uint8_t reg`

C передає аргументи **копією** (by value). Якби параметр був просто `uint8_t reg`,
функція міняла б свою локальну копію, а оригінал лишався б незмінним. Тому передаємо
**адресу** регістра:

- `uint8_t *reg` — параметр-**вказівник** («адреса байта»);
- `*reg` — **розіменування**: «значення за цією адресою», тобто сам оригінал;
- у виклику `set_bit(&gpio_reg, 2)` — `&gpio_reg` дає **адресу** змінної.

> PHP-аналогія: як параметр `&$var` за посиланням — лише в C це явно через адресу/вказівник.
> ⤳ вказівники глибше — M2.

## `print_reg`: друк байта у двійковому вигляді

`printf` не має `%b`, тому друкуємо вручну — від **старшого** біта (7) до молодшого (0),
щоб читалось зліва направо. Перевірка одного біта: `reg & (1u << i)` — «І з маскою»
лишає або сам біт, або 0; тернар перетворює це на `'1'`/`'0'`.

## Перевірка через `assert`

Замість «звіряння очима» після кожної операції стоїть `assert(gpio_reg == 0x..)`.
Дійшли до `return 0` і жоден assert не впав = вправа робоча. ⤳ повноцінні unit-тести
(Unity/CppUTest) — M2/M6.

## Нюанс реального заліза (щоб модель не закарбувалась буквально)

Наш `uint8_t` — спрощення. На STM32:

- ніжки згруповані в **порти** (`GPIOA`, `GPIOB`, …); біт N у регістрі порту = pin N
  **цього порту** (біт 5 у `GPIOA` → ніжка `PA5`);
- регістр порту зазвичай **ширший за 8 біт** (на STM32 — 16, тобто `PA0…PA15` в одному
  регістрі);
- на реальному залізі регістр оголошують як `volatile uint8_t*` за фіксованою адресою
  (**MMIO**): `volatile` забороняє компілятору кешувати/викидати доступ, бо значення може
  змінити саме залізо (натиснули кнопку), а не наш код;
- на **ESP32/Arduino** `digitalWrite(2, …)` — це **логічний** номер ніжки, який шар
  Arduino мапить на конкретний порт+біт; тож «pin 2» там ≠ «біт 2 одного байта» напряму.
  У цьому хост-прикладі ми навмисно прибрали цей шар і показали «голий» зв'язок біт↔pin.

Принцип «біт N керує ніжкою N» — справжній, але діє **в межах одного порту**, і порт
буває ширший за байт. ⤳ реальні `GPIOx`-регістри й порти — M3 (MMIO) і M5 (GPIO, clock tree).

```bash
gcc -Wall -Wextra -std=c11 reg.c -o reg   # попередження — перша лінія проти UB

```
