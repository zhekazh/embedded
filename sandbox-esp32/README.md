# sandbox-esp32 — пісочниця для реальної плати ESP32

> **Статус:** 🔄 в роботі
> **Що це:** вільна тека для експериментів на **фізичному** ESP32 (не модуль із M0…M12).
> Тут можна ламати, переписувати й пробувати що завгодно без оглядки на «критерій
> переходу».
> **Залізо:** ESP32 DevKit (esp32dev, WROOM-32), USB-UART міст **FTDI FT232R** (COM3),
> макетна плата, OLED 0.96" SSD1306 (I2C 0x3C).

## Поточний артефакт
Демо для **OLED SSD1306 128×64 по I2C** ([src/main.cpp](src/main.cpp)): текст, лічильник
кадрів, прогрес-бар, відбивний квадратик + друк реального часу кадру в Serial (видно
межу I2C по FPS). Швидкий шлях — через бібліотеку `Adafruit SSD1306` (власний драйвер з
нуля — ціль M5, не тут).

## Робочий процес: Wokwi → реальна плата
На відміну від «чистого заліза», тут є і Wokwi (`wokwi.toml` + `diagram.json`), але з
іншою роллю: **спершу зібрати й перевірити схему/код в емуляторі**, тоді переносити на
макетку. Wokwi запускає раніше зібраний `.elf`, тож цикл: правка → `pio run` → перезапуск
симулятора.

## Схема (ESP32 ↔ OLED, I2C через шини живлення макетки)
| OLED SSD1306 | ESP32 | Колір |
|---|---|---|
| VCC | 3V3 (через шину `+`) | червоний |
| GND | GND (через шину `−`) | чорний |
| SDA | GPIO21 | зелений |
| SCL | GPIO22 | синій |

Додаткових елементів **не треба**: pull-up на SDA/SCL і конденсатор розв'язки вже на
платі модуля. Резистор-обмежувач/діод не потрібні.

## Передумови
- PlatformIO (CLI або VS Code-розширення).
- Драйвер USB-UART. У цій плати — **FTDI FT232R** (VID:PID `0403:6001`), у Windows
  стає як «USB Serial Port».

## Запуск (відтворюваний з нуля)
1. Підключи плату по USB, перевір, що ОС її бачить:
   ```bash
   pio device list
   ```
   _Перевірка:_ є COM-порт (тут `COM3`), опис `USB Serial Port`.
2. Збери прошивку (перший раз підтягне бібліотеки):
   ```bash
   pio run
   ```
   _Перевірка:_ `SUCCESS`, граф залежностей містить `Adafruit SSD1306`/`GFX`, з'явився
   `.pio/build/esp32dev/firmware.bin`.
3. (Опційно) перевір схему в Wokwi: `Ctrl+Shift+P` → **Wokwi: Start Simulator** → ▶.
   _Перевірка:_ на віртуальному OLED — текст і анімація, у Serial біжать кадри.
4. Прошити реальну плату й відкрити монітор:
   ```bash
   pio run -t upload -t monitor --upload-port COM3
   ```
   _Перевірка:_ на фізичному OLED та сама картинка; у моніторі (115200) `OLED OK` і
   `frame N: ~XX ms/кадр`.

## Граблі / лог факапів
> Симптом → причина → фікс. Матеріал для співбесіди.
- **Правки в коді не видно в Wokwi** → симулятор стартує раніше зібраний `.elf`, а не
  поточний `main.cpp` → після кожної правки `pio run`, тоді перезапустити симулятор.
- **`SSD1306: не знайдено на 0x3C`** → найчастіше макетка: пін модуля і кінець перемички
  в РІЗНИХ стовпцях (висить у повітрі), переплутані SDA/SCL, або живлення не дійшло до
  рейки → пройтись по стовпцях; частина модулів має адресу `0x3D` (тоді правити `OLED_ADDR`).
- **Низький FPS (~10 замість ~25)** → I2C на дефолтних 100 кГц → `Wire.setClock(400000)`
  (fast mode); це наочно показує, що пляшкове горло — шина, а не панель.
- **Ризик (уникнули):** живлення з `5V`/`VIN` замість `3V3` або переплутана полярність —
  захисного діода в схемі немає, спалює модуль → завжди звіряти VCC→3V3, GND→GND двічі.
