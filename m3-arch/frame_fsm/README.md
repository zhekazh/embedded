# M3 · frame_fsm — байтовий кінцевий автомат кадру

> **Статус:** ✅ закрито
> **Що демонструє:** подієвий (event-driven) кінцевий автомат — байт-за-байтом
> знаходить межі кадру STX/ETX, ігнорує шум до старту й **ресинхронізується** на
> вкладеному STX. Неблокуючий: жодного `delay`/очікування.
> **Залізо:** не потрібне — усе на хості (gcc + make).

## Мета
Відпрацювати кінцевий автомат як основу надійного прийому: замість «зчитати рівно
N байтів» — реагувати на кожен байт і завжди мати визначений стан, навіть на смітті
в лінії. Це мінімальний кадр (`STX · DATA · ETX`), на якому видно ідею; повний
кадровий кодек (COBS+CRC) — у [M2 frame-codec](../../m2-c/frame-codec/README.md).

## Теорія (стисло)
- **Три стани** ([frame_fsm.h](src/frame_fsm.h)): `WAIT_STX` → `WAIT_DATA` → `WAIT_ETX`.
  `STX=0x02`, `ETX=0x03`, payload — 1 байт.
- **Подієвість.** `fsm_feed(f, b, &out)` ковтає один байт і повертає `true` рівно
  коли щойно завершився валідний кадр (`*out = payload`). Нічого не чекає, не блокує —
  лягає прямо на «ISR віддав байт → автомат просунувся».
- **Шум до STX** ігнорується (лишаємось у `WAIT_STX`).
- **Ресинхронізація.** Якщо у `WAIT_ETX` прийшов не-ETX: на `STX` — це початок нового
  кадру (→ `WAIT_DATA`), інакше — назад у `WAIT_STX`. Тобто збитий кадр не «отруює»
  приймач — наступний коректний кадр буде розпізнано.

## Запуск (відтворюваний з нуля)
```bash
cd m3-arch/frame_fsm
make test       # Unity під ASan/UBSan
```
_Перевірка:_ `4 Tests 0 Failures 0 Ignored / OK` — чистий кадр; шум до STX;
ресинк на вкладеному STX; back-to-back (два кадри поспіль).

```bash
make lint       # cppcheck
```
_Перевірка:_ без знахідок (exit 0).

## Граблі / лог факапів
> Симптом → причину → фікс.
- **`make test` → «Ціль "test" не вимагає виконання команд»** → причина: у теці не
  було `Makefile`, тож `make` бачив наявну теку `test/` як готову однойменну ціль і
  вважав, що робити нічого; фікс: додав `Makefile` (за зразком host-C `m2-c/frame-codec`).
- **`return false` наприкінці `fsm_feed` — формально недосяжний** → причина: усі гілки
  `switch` уже повертають, але без фінального `return` `gcc -Wall` свариться на
  «control reaches end of non-void function»; фікс: лишив явний `return false`
  (повний шлях > мовчазне покладання на охоплення `switch`).
