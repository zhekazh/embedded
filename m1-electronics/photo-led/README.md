# M1 · photo-led — фоторезистор керує яскравістю LED

> **Статус:** 🔄 в роботі
> **Що демонструє:** повний аналоговий пайплайн на мікроконтролері — сенсор → АЦП → обробка → PWM-вихід, відтворюваний у симуляторі без фізичного заліза
> **Залізо:** емулятор (Wokwi); LDR-модуль, LED, резистор 220 Ω — у симуляції

## Мета
Зчитати освітленість фоторезистором через АЦП ESP32 і пропорційно керувати яскравістю LED через PWM. Це наскрізна демонстрація того, як аналоговий світ (напруга) перетворюється на число, обробляється і знову стає фізичним сигналом (яскравість).

## Теорія (стисло)
> Загальна теорія (АЦП, PWM, дільник) — у [README модуля](../README.md). Тут лише специфіка проєкту.

- **Дільник уже вшитий у компонент.** `wokwi-photoresistor-sensor` містить LDR послідовно з резистором 10 кΩ; пін `AO` знятий між ними. Тому окремий дільник руками не збираємо — світло змінює напругу на `AO`. Світліше → менший опір LDR → більша напруга на `AO`.
- **АЦП ESP32:** `analogRead()` повертає 0…4095 (12 біт).
- **PWM на ESP32 (Arduino core 3.x):** `analogWrite(pin, 0..255)` сам піднімає апаратний PWM (LEDC, 1 кГц, 8 біт). Старий API `ledcSetup`/`ledcAttachPin` на core 3.x не компілюється.
- **Зв'язка:** `map(raw, 0, 4095, 0, 255)` масштабує код АЦП у duty cycle.

## Передумови
- Wokwi: сайт (wokwi.com) **або** локально VS Code + PlatformIO (профіль ESP32 з M0).
- Для локального PlatformIO скетч лежить як `src/main.cpp` і потребує `#include <Arduino.h>` зверху; на сайті це `sketch.ino` без інклуду.

## Запуск (відтворюваний з нуля)
1. **Wokwi → New Project → ESP32.**
   _Перевірка:_ відкрився редактор зі `sketch.ino` і `diagram.json`.
2. Додай компоненти (кнопка «+» у діаграмі): `Photoresistor (LDR) Sensor`, `LED`, `Resistor` (постав `value = 220`).
3. З'єднай:

   | Від | До |
   |---|---|
   | LDR `VCC` | ESP32 `3V3` |
   | LDR `GND` | ESP32 `GND` |
   | LDR `AO` | ESP32 `GPIO34` (АЦП-вхід, input-only) |
   | ESP32 `GPIO5` | резистор → анод LED |
   | катод LED | ESP32 `GND` |

   _Перевірка:_ немає висячих виводів; пін `DO` модуля не задіяний.
4. Встав код зі `src/main.cpp` у скетч (на сайті — без рядка `#include <Arduino.h>`).
5. **Run** → відкрий **Serial Monitor**, швидкість **115200**.
   _Перевірка:_ біжать рядки `ADC=… duty=…`.
6. **Клікни по фоторезистору** в симуляції → з'явиться повзунок lux → тягай.
   _Перевірка:_ темно → малий ADC → тьмяний LED; яскраво → великий ADC → яскравий LED.

## Граблі / лог факапів
> Симптом → причину → фікс.
- **Помилка компіляції на PWM** → причина: старий API `ledcSetup`/`ledcAttachPin` (core 2.x), а Wokwi за замовчуванням ставить core 3.x → фікс: `analogWrite(pin, duty)` або новий `ledcAttach(pin, freq, res)` + `ledcWrite(pin, duty)`.
- **LED не світиться, хоч код «крутиться»** → причина: LED повісили на input-only пін (34/35/36/39) → фікс: LED тримати на звичайному виводі (GPIO5); input-only лишити під `AO`.
- **У Serial Monitor «ієрогліфи»** → причина: швидкість монітора ≠ `Serial.begin(115200)` → фікс: виставити 115200.
- **Яскравість «не та» (інверсія)** → причина: бажаний нічник (темрява → яскраво) при прямому мапінгу → фікс: `map(raw, 0, 4095, 255, 0)`.
