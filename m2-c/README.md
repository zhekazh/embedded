# M2 · C по-справжньому (хост, unit-тести)

> **Статус:** ✅ закрито
> **Критерій переходу:** пишу ring buffer і парсер протоколу без підказок; тести зелені в CI під ASAN/UBSAN.
> **Залізо:** не потрібне — увесь модуль на хості (gcc + make)

## Мета
Перестати «писати на C як на пітоні» й почати відповідати за кожен байт: час
життя, розкладку пам'яті, вирівнювання, endianness, бітові операції — і ловити
UB інструментами, а не очима. На виході — робастний wire-кодек (COBS-framing +
CRC-16 + ring buffer + RX-стейтмашина) на чистому C з unit-тестами, який прямо
лягає в кадрові протоколи далі (⤳ MAVLink у M8).

## Підпроєкти

- [explore/](explore/) — п'ять коротких програм-розвідок: вказівники/арифметика,
  час життя (dangling), розкладка пам'яті, alignment/packing, endianness.

## Теорія (стисло, своїми словами)
- **Масив ≠ вказівник, але `a[i]` — це буквально `*(a + i)`.** Арифметика
  масштабується типом елемента (`&a[1]-&a[0]` = `sizeof(elem)`). У параметрі
  функції масив «розпадається» на вказівник, тому `sizeof(arr)` всередині дає
  розмір **вказівника**, а не масиву — класична пастка ([ptr_arith.c](explore/ptr_arith.c)).
- **Час життя.** Локалка живе разом зі своїм стек-фреймом; повернути на неї
  вказівник = читати мертву пам'ять. І головне: **UB ≠ гарантований краш** —
  без санітайзера таке часто «працює» (друкує старе значення, exit 0), поки
  одного разу не зруйнується ([dangle.c](explore/dangle.c)).
- **Розкладка процесу:** `.text` (код), `.data` (ініціалізовані глобали/статики),
  `.bss` (нульові глобали), купа (`malloc`), стек (локалки) — кожне у своєму
  діапазоні адрес ([mem_map.c](explore/mem_map.c)). ⤳ деталі секцій і linker
  script — M3.
- **Alignment / packing.** Компілятор додає padding, щоб поля лягали на свої межі
  вирівнювання; порядок полів змінює `sizeof` структури при тих самих даних
  ([layout.c](explore/layout.c)). ⤳ критично для wire-структур і регістрових мап.
- **Endianness і серіалізація.** Не лити структуру в дріт через `memcpy` — порядок
  байтів залежатиме від хоста. Серіалізувати **через значення** (зсуви
  `>> 8 & 0xFF`), тоді на лінії фіксований порядок незалежно від платформи
  ([endian.c](explore/endian.c)). У кодеку CRC пишеться little-endian саме так.
- **Бітові операції** — маски/зсуви для set/clear/toggle; основа і регістрів, і
  cobs/crc. (База відпрацьована ще в [m0-blink/host-c](../m0-blink/host-c/README.md).)
- **`volatile` / `const` / `static` / `stdint.h`.** Тут — фіксовані ширини
  (`uint8_t`/`uint16_t`) скрізь. `volatile` свідомо **не** ставив: на хості в
  одному потоці він не потрібен і лише гальмує. ⤳ він стане обов'язковим для MMIO
  та ISR-safe ring buffer у M3.
- **COBS (Consistent Overhead Byte Stuffing).** Кодування прибирає з даних усі
  нулі, щоб `0x00` можна було використати як **роздільник кадрів**. Накладні —
  ~1 байт на кожні 254 байти. Декодер відновлює нулі за код-байтами.
- **CRC-16/CCITT-FALSE** (poly `0x1021`, init `0xFFFF`, без рефлексії та фінального
  XOR; контрольне значення для `"123456789"` = `0x29B1`). Ловить **випадкові**
  пошкодження лінії — це не криптопідпис (від зловмисника не захищає).
- **Кадр на лінії:** `COBS( payload || crc16_le(payload) )` + завершальний `0x00`.
  RX-сторона накопичує байти до роздільника, потім декодує й перевіряє CRC; биті
  кадри тихо відкидає, на overflow ре-синкається до наступного `0x00`.
- **SPSC ring buffer.** Корисна місткість = `size − 1` (один слот жертвуємо, щоб
  відрізнити повний від порожнього). Кожна сторона пише лише свій індекс. ⤳ цей
  самий патерн у **ISR-safe** варіанті (ISR-producer → main-consumer) розгорнемо
  в M3/M7 — і там звичайних `size_t` уже **не вистачить** (див. граблі).
- **UB — головний ворог.** Перша лінія оборони: `-Wall -Wextra -Werror` на своєму
  коді + **ASAN/UBSAN** на кожному тесті + **cppcheck**. (MISRA-C — стандарт
  де-факто в safety/defense; поки лише на радарі.)

## Артефакти цього модуля
- `frame-codec/` — COBS + CRC-16 + framing + RX-стейтмашина + SPSC ring buffer на
  чистому C з повним набором unit-тестів (round-trip, відомі вектори, негативні
  кейси: пошкодження, обрізаний кадр, overflow+ре-синк, прохід через ring buffer).
- `explore/` — п'ять програм-розвідок (вказівники, час життя, розкладка пам'яті,
  alignment, endianness) з чесним `make`-таргетом.

## Безпека / захист
- **Вхідна валідація wire-даних:** `cobs_decode` і `frame_parse` перевіряють межі
  виходу (`out_cap`) і відкидають биті/обрізані кадри **без переповнення** буфера —
  підтверджено ASAN на негативних тестах. Декодування йде у стекові буфери
  фіксованого розміру, обмежені `FRAME_MAX_PAYLOAD`.
- **Цілісність ≠ автентичність:** CRC-16 ловить випадкові пошкодження лінії, але не
  зловмисника (це не MAC/підпис). ⤳ автентичність кадру (підпис/лічильник проти
  replay) — пізніше, на рівні протоколу (MAVLink, M8).

## Граблі / лог факапів
- **`dangle` «успішний», хоч це UB** → причина: читання мертвого стек-фрейму не
  зобов'язане падати — слот ще не перезаписано, тому друкує старе значення й
  exit `0`; фікс/урок: ловити санітайзером — під ASAN з
  `detect_stack_use_after_return` це `stack-use-after-return`, тому explore-таргет
  ганяє `dangle` під ASAN і **очікує** аварію (якщо exit `0` — ламаємо таргет).
- **`make` у explore: «Циклічна залежність» + «cannot open output file build/…»**
  → причина: фоні-таргет назвав `build` так само, як каталог збірки `$(B)=build`,
  і order-only-залежність `| build` чіплялась за фоні-ціль (яка залежить від
  бінарників) замість правила, що створює каталог → `mkdir` не виконувався; фікс:
  перейменував агрегат `build` → `all`, каталог лишив `build`.
- **ring buffer не ISR-safe як написаний** (forward, ⤳ M3/M7) → причина: `head`/
  `tail` — звичайні `size_t` без `volatile`/`_Atomic`; компілятор має право
  закешувати індекс у регістрі, а порядок «спершу `buf[head]=byte`, потім
  публікація `head`» нічим не гарантований. Структура SPSC правильна, але типів
  замало; фікс на single-core Cortex-M: `volatile` на індекси + компайлерний
  бар'єр (або `_Atomic` release/acquire) + явний порядок «дані → бар'єр → індекс».
  На хості в одному потоці проблеми нема — тому тести зелені, і це присипляє.
- **Глибокий стек на RX-шляху (~520 Б)** → причина: `frame_rx_push` тримає
  `payload[256]`, а викликаний `frame_parse` зверху бере ще `tmp[258]` — піки
  складаються; фікс/мітигація: декодувати COBS прямо в буфер викликача (без
  проміжного `tmp`), або зменшити `FRAME_MAX_PAYLOAD` під реальний кадр. На хості
  байдуже, на малому MCU — рахувати.
- **`reg`-бінарник без розширення не ловився `.gitignore`** → причина: правила
  ігнору були за розширеннями (`*.o/*.i/*.s`), а виконуваний `m0-blink/host-c/reg`
  розширення не має → закомітився б на `git add`; фікс: явний шлях у `.gitignore`
  (m2 цього уник, бо складає все в ігнорований `build/`).
- **Рішення (щоб не передумувати):** `explore/` свідомо тримаємо **поза `-Werror`**
  — це розвідка з навмисними гострими краями (`ptr_arith.c` дає
  `-Wsizeof-array-argument`, і в цьому урок); `#pragma` в навчальний файл не ховав,
  щоб не захаращувати. Кореневий demo-харнес (`add()` + закоментований
  sanitizer-тест) відіграв роль на кроці 0 і був видалений як шум — живий
  «sanitizer bites» лишився як `explore/dangle.c`. `% size` у ring buffer лишив
  заради ясності (степінь-двійки + маска — перф-ідіома на потім).
