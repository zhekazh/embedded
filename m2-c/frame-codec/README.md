# M2 · frame-codec — байтовий фреймінг серійного потоку

> **Статус:** ✅ закрито (функціонально; CI підтверджується після пушу)
> **Що демонструє:** чистий C — модульний API з перевіркою меж, host unit-тести під ASAN/UBSAN, CI зі статичним аналізом; робастний розбір кадрів зі стійкістю до пошкоджень і ресинком.
> **Залізо:** не потрібне — усе на хості (gcc/WSL). Логіка цілком переноситься на МК (див. «Відомі обмеження»).

## Мета

Зібрати з нуля надійний шлях «потік байтів → валідні кадри»: SPSC кільцевий буфер
приймає байти, кінцевий автомат знаходить межі кадрів, де-фреймить (COBS),
перевіряє цілісність (CRC-16) і віддає тільки коректне навантаження, тихо
відкидаючи биті, обрізані чи переповнені кадри. Усе під unit-тестами й
санітайзерами, з відтворюваною збіркою.

## Теорія (стисло)

Кадр на лінії (між роздільниками `0x00`):

```
payload
  → payload ‖ crc16_le(payload)     (+2 байти, little-endian)
  → COBS( … )                       (прибрали всі нулі)
  → COBS( … ) ‖ 0x00                (+роздільник)   = кадр на лінії
```

- **COBS** (Consistent Overhead Byte Stuffing) робить вміст zero-free, щоб `0x00`
  міг бути однозначним роздільником кадрів; оверхед обмежений (≤1 байт на 254).
- **CRC** рахуємо *до* COBS — щоб самі байти CRC теж стали zero-free й не зламали
  роздільник. Використано CRC-16/CCITT-FALSE (poly `0x1021`, init `0xFFFF`;
  контрольне значення для `"123456789"` = `0x29B1`).
- **SPSC ring buffer**: `head` пише лише продюсер, `tail` — лише консюмер; один
  слот жертвується на розрізнення повний/порожній. Модель «продюсер ↔ консюмер»
  лягає на «ISR пише → main читає» (з застереженням, див. «Відомі обмеження»).

## Модулі

| Модуль | Призначення |
|---|---|
| `ringbuf` | SPSC байтовий кільцевий буфер; сховище дає викликач, без `malloc` |
| `cobs` | COBS encode/decode з перевіркою меж вихідного буфера |
| `crc16` | CRC-16/CCITT-FALSE (бітовий) |
| `frame` | `frame_build` / `frame_parse`: payload+CRC поверх COBS |
| `frame_rx` | кінцевий автомат-приймач: байт-за-байтом → валідний payload у callback |

Наскрізний конвеєр: `байти → ringbuf → frame_rx (де-фреймінг + CRC) → callback`.

## Запуск (відтворюваний з нуля)

```bash
git clone <repo-url> embedded
cd embedded/m2-c/frame-codec
make test
```
_Перевірка:_ п'ять runner-ів (`cobs`, `crc16`, `frame`, `frame_rx`, `ringbuf`),
кожен закінчується `N Tests 0 Failures 0 Ignored / OK` (разом 31 тест).

```bash
make lint
```
_Перевірка:_ `cppcheck` проходить усі файли `src/` без знахідок (exit 0).

Збірка суворого host-коду: `-std=c11 -Wall -Wextra -Werror` + ASAN/UBSAN
(`-fno-sanitize-recover=all`). Опції рантайму вшито в ціль `test`
(`detect_leaks`, `detect_stack_use_after_return`, `print_stacktrace`).

## Граблі / лог факапів

- **`make test` → «пропущено розділювач» (missing separator).** Причина: рецепти
  Makefile із пробілами замість табів (наслідок копіювання). Фікс: таб на початку
  рецептів; швидке нормалізування `sed -i 's/^ \+/\t/' Makefile` (до Makefile — так,
  до YAML — ніколи).
- **Тести валились `implicit declaration of cobs_*`, а `cat src/cobs.h` показав порожній файл.**
  Причина: heredoc не вставив тіло; порожній `.h` проходить `gcc -fsyntax-only`
  («header OK» оманливе). Фікс: перестворити файл і одразу `wc -l` як перевірку, що
  він не порожній.
- **`dangle`-демо тихо друкувало `777` замість злову use-after-return.** Причина:
  `detect_stack_use_after_return` вимкнено за замовчуванням у цьому libsanitizer.
  Фікс: `ASAN_OPTIONS=...:detect_stack_use_after_return=1` (вшито в `make test`).
  Урок: тихий/зелений запуск не доводить коректності — покриття залежить від
  конфігурації санітайзера.
- **clang-only прапорець `-fsanitize-address-use-after-return=always` відкинуто gcc.**
  Причина: у gcc цієї перевіркою керує лише рантайм-опція, не прапорець компіляції.
  Фікс: керувати через `ASAN_OPTIONS`. (Перевіряти прапорці тулзів емпірично, не з пам'яті.)
- **На overflow-демо першим спрацював UBSAN (`object-size`), а не ASAN.** Причина: з
  `-fno-sanitize-recover=all` падає перша ж перевірка, що зловила; UBSAN-перевірка
  інлайниться на інструкції запису. Не баг — тримаємо обидва санітайзери, вони
  перекривають різні класи помилок.
- **Два `main()` при додаванні другого тест-файлу.** Причина: Unity має один `main`
  (і один `setUp`/`tearDown`) на виконуваний файл. Фікс: Makefile будує окремий
  runner на кожен `test/test_*.c` і ганяє всі в циклі.

## Відомі обмеження (на потім)

- **SPSC ring buffer структурно коректний, але як є — не ISR-safe.** Індекси —
  звичайні `size_t` без `volatile`, немає гарантованого порядку «спершу `buf[head]`,
  потім публікація `head`» і компайлерного бар'єра. На хості (один потік) усе
  працює; для реального «ISR пише ↔ main читає» на Cortex-M треба додати `volatile`
  на індекси + бар'єр + порядок запису. ⤳ повертаємось у M5/M7.
- **Пік стеку RX-шляху ~520 байтів** (`payload[256]` у `frame_rx_push`, поки
  `frame_parse` тримає `tmp[258]`). На хості байдуже, на малому MCU помітно.
  Мітигація: декодувати прямо в буфер викликача / зменшити `FRAME_MAX_PAYLOAD`.
- **`%` у ring buffer** обрано заради ясності; embedded-перф-ідіома — розмір
  степінь-двійки + бітмаска (`& (size-1)`) замість ділення.

## CI

GitHub Actions (`.github/workflows/ci.yml`, корінь репо) на кожен push:
`make test` (збірка + усі runner-и під санітайзерами) + `make lint` (cppcheck).
Обсяг CI свідомо обмежено **host-логікою + статичним аналізом** — саме тим, що є
суттю цього модуля; збірка прошивок (емуляторні m0/m1) у CI не входить, бо тулчейн
у раннері надто дорогий за низької цінності.
